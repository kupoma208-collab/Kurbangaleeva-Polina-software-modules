Ответ: входные: a, b - стороны прямоугольника; выходные: S - площадь, P - периметр; промежуточные: S и P - накопители результатов вычислений.

1.	Сформулируйте назначение алгоритма.
Ответ: алгоритм находит максимальное из двух чисел a и b: при a ≥ b результатом становится a, иначе - b. Результат выводится как m.
2.	Выполните ручную проверку для пар (9; 4), (−3; 2), (5; 5).
3.	Для каждой пары укажите результат условия, выбранную ветвь и вывод.
Пара	Проверка a ≥ b	Результат условия	Выбранная ветвь	m	Вывод

4.	Объясните, что изменится при замене условия a ≥ b на a > b: изменится ли результат, и изменится ли выбранная ветвь для равных чисел?
Ответ: результат не изменится ни для одной пары: 9, 2, 5; выбранная ветвь для равных чисел изменится: при a ≥ b для (5; 5) выбирается «Да» (m ← a), а при a > b условие 5 > 5 ложно → выбирается «Нет» (m ← b). Значение m остаётся 5, но путь выполнения другой - это важно, если ветви содержат не только присваивание.

4.	Объясните назначение начальных значений S и i.
Ответ: S ← 0 - начальное значение накопителя суммы; без него нельзя выполнить S ← S + i. Ноль - нейтральный элемент для сложения. i ← 1 - начальное значение счётчика, оно задаёт первое число, которое будет прибавлено к сумме; первое прибавляемое число. Без инициализации проверка i ≤ N и S ← S + i были бы неопределены.
5.	Объясните, почему при допустимом N цикл завершается.
Ответ: при каждом проходе i увеличивается на 1 (i ← i + 1). Так как N - целое и N ≥ 0, а i начинает с 1 и монотонно растёт, рано или поздно i станет больше N (при N = 0 - сразу). Условие i ≤ N станет ложным, цикл завершится. Условие проверяется до тела, поэтому выход всегда достижим.
Задание 5. Поиск и исправление ошибок
Случай A. Неверные фигуры и отсутствующий переход. В схеме из задания 2 ввод a, b помещён в прямоугольник, вычисление S - в параллелограмм, а между вычислением P и выводом отсутствует стрелка.
Ошибка: ввод a, b - в прямоугольнике вместо параллелограмма; вычисление S - в параллелограмме вместо прямоугольника; между P и выводом нет стрелки.
Последствия: схема читается неверно (непонятно, где ввод, а где вычисление); отсутствие стрелки нарушает порядок выполнения.
Исправление: ввод a, b - в параллелограмм; S ← a · b - в прямоугольник; добавить стрелку от P ← 2 · (a + b) к «Вывод S, P».

Ответы на контрольные вопросы:
1. Для чего используется блок-схема?
Ответ: для наглядного представления алгоритма - она показывает действия и порядок переходов между ними с помощью геометрических фигур и стрелок.
2. Как обозначаются ввод, вычисление и условие?
Ответ: ввод/вывод - параллелограммом, вычисление (действие) - прямоугольником, условие - ромбом.
3. Чем присваивание отличается от проверки равенства?
Ответ: присваивание (S ← a + b) записывает в величину новое значение, а проверка равенства сравнивает значения и даёт логический результат, ничего не изменяя.
4. Чем следование отличается от ветвления?
Ответ: при следовании действия выполняются последовательно, а при ветвлении условие определяет дальнейший путь, и при одной проверке выполняется только одна выбранная ветвь.
5. Может ли тело цикла с предварительной проверкой не выполниться ни разу?
Ответ: да, если условие при первой проверке сразу ложно, тело цикла не выполняется ни разу.
6. Для чего задают начальное значение накопителя?
Ответ: чтобы величина была определена до её использования - в записи S ← S + i справа берётся прежнее значение S, поэтому оно должно быть задано заранее.
7. Что может произойти без изменения счётчика цикла?
Ответ: условие продолжения никогда не станет ложным, поэтому цикл не завершится - у цикла должен быть достижимый выход.
8. Почему нужно проверять случай равных чисел?
Ответ: потому что при равенстве нестрогое условие (≥) истинно, а строгое (>) ложно - это меняет выбранную ветвь, и проверка граничного случая выявляет ошибки.
9. Что показывает таблица трассировки?
Ответ: пошаговое выполнение алгоритма - выполненный блок, значения величин после действия и результат проверки условия или переход.
10. Почему успешной проверки на одном примере недостаточно?
Ответ: проверка на отдельных примерах помогает обнаруживать ошибки, но не доказывает правильность алгоритма для всех возможных данных.
